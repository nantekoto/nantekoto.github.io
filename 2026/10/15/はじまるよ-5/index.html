はじまるよ~博客搭建日志 5

2026年10月15日 博客搭建 约984字 预计需要3分钟

梓喵还没醒，博客已经快放了四年了（悲）。

上一篇搭建日志结尾写的是「又要忙报告，之后再说啦」。这个「之后」稍微有点久。

这次让 Codex 接手检查了一遍，把框架、依赖和当年连蒙带猜改进去的东西整理一下。页面整体没什么大变化。

主题位置

以前装 Nexmoe 的时候，是直接在 node_modules/hexo-theme-nexmoe 里面改文件的。访问统计、Waline，还有几个页面的布局，都写在别人的包里。

现在再看，重新安装依赖会把这些修改全冲掉。

所以这次先把原来的主题完整复制出来，放到：

站点配置仍然是：

只是以后要改模板，就去这个目录里改。原来的评论、统计和页面布局都保留，npm 里面的 Nexmoe 依赖则移除了。

这次没有顺便追主题的新版本。先把自己当年改过什么保住，不然升级完发现评论没了，又要对着四年前的日志重新蒙古里。

框架和依赖

Hexo 从 6.3.0 升到了 7.3.0，Markdown 渲染器从 6.0.0 升到 6.3.0，Stylus 渲染器从 2.1.0 升到 3.0.1。

本来还可以继续往 Hexo 8 走，但电脑上的 Node 还是 18.12.1。暂且先停在能验证通过的版本，之后再处理运行环境。

顺便跑了一下 npm audit，第一次报了 39 项依赖问题，其中 2 项 critical。

能正常生成网页就说明一切正常

做完兼容的修复以后，降到了 17 项，8 项 high、9 项 moderate，critical 清零。剩下的有一些挂在 Hexo 的工具依赖上，还有一些是音乐插件带进来的老包，暂时没有合适的修复版本。

一些细枝末节

站点的 url 之前还是 HTTP，现在改成 HTTPS。时区也明确设为 Asia/Hong_Kong。

然后是 Google Analytics。

当年在日志里写，把跟踪代码丢进 <head> 就好了。结果页面里有两份加载代码和初始化。

生成检查

以前的流程大概是：改代码，生成，打开首页看看，感觉没炸，发。

codex让我多加一道检查命令：

前一个负责生成网页，后一个检查生成页面里的本地链接和资源是否存在，也会检查站内 HTTP 地址和重复的 Analytics 加载代码。

当然，这不代表评论服务、外链和播放器都被自动测了一遍。脚本主要负责找本地文件和页面里的几类问题。

还有一个没解决的坑：npm run clean 清理 public/css 的时候会报 EPERM。项目放在 OneDrive 里，目前还没确认究竟是哪一层的权限或者文件状态出了问题。重新生成倒是能成功，但之后如果删除文章或者资源，就不能想当然地以为旧文件也一定清干净了。

先记在这里，免得下次又从头查。

其他

让codex补了 README 和维护记录。

另，.deploy_git 管的是生成以后拿去发布的网页，源码目录本身还没有建立 Git 仓库。之后可能会补上，也可能不会。

Task list

  • 把改过的主题从 node_modules 里搬出来
  • 更新 Hexo、渲染器和能兼容修复的依赖
  • 修一下 HTTPS、时区和默认文章模板
  • 去掉重复统计代码和不存在的样式引用
  • 加上生成后的检查，重新部署
  • 更新 Node，再看看 Hexo 8
  • 剩下的依赖问题，尤其是音乐插件那串老包
  • 搞清楚 clean 为什么删不掉目录
  • 给源码也建一个 Git 仓库
  • 本地搜索、关于博主、个人域名……

暂且修到这里，希望下一篇不用再等四年。じゃあ~
